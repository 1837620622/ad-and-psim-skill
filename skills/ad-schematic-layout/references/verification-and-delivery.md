# 网表、图面与交付核验

## 电气与视觉分开验收

| 层面 | 应取得的证据 | 不能据此声称 |
|---|---|---|
| 文件结构 | 原生文档读取成功、引用路径和依赖可用 | 电路正确 |
| 网络 | 实际引脚、参数、原生编译与网表一致 | PCB 或实物已经合格 |
| 图面 | 原生全图、关键局部、打印比例审阅 | 已完成器件额定值或制造检查 |
| 交付 | 清单、CRC、解压哈希和解压复开 | 其它软件版本已实测兼容 |

保存后重新打开工程。使用新副本复核可避开同路径旧文档仍在内存的问题；副本应完整包含工程及引用，不只拷贝孤立 SchDoc。不要覆盖用户未保存的会话。

分别统计 Error、Fatal、Warning 和取消状态。零错误不能写成零警告；也不能用关闭报告级别制造“通过”。缺封装模型可在仅原理图的任务中说明边界，但有了 PCB 制造要求就必须处理封装与焊盘映射。

## 逐引脚网表比较

推荐原生导出每行三字段：`网络名|物理位号|引脚编号`，例如：

```text
+3V3|U1|29
+3V3|C1|1
DGND|C1|2
```

独立检查结果也可提供 JSON：`{"pin_map":{"U1.29":"+3V3","C1.1":"+3V3","C1.2":"DGND"}}`；此格式还兼容含有其它审阅字段的外层对象。

```text
python scripts/compare_pin_nets.py expected.json native-nets.txt --output check.json
```

工具以引脚的同网伙伴比较拓扑，自动生成的网名变动不会造成误报。缺脚、增脚、合网或断网会失败；一个物理引脚重复归属会被拒绝。工具不会判断某个连接本来是否应该存在，预期网表必须来自可信设计，而不是直接复制待检网表。

同网判断不能只按几何距离或所有线段相交建立。意图导通的四向连接需要真实电气端点和原生网表证据；本机个案中仅保留连续交叉线与显示圆点仍出现断网，在交点处分段后原生验证才与独立检查一致。

## 原生出图与多轮查看

优先原生打印/导出。原生脚本绘图可使用已验证的 `ISch_Document.RedrawToDC` 路线，但接口、边界和缩放要现场检查。不要为了输出临时关闭工作文件的图框；需要更改显示选项时在副本上做。

若 EMF 转位图时画布为空或被裁切，先检查原生图形边界、EMF 设备边界与物理 frame 的关系。保留原始导出；规范容器元数据不等于重画图元，不得借此拉伸器件或遮住错误。

```text
python scripts/review_emf_text.py drawing.emf --output text-review.json
```

可按实际图框传入 `--border "xmin,ymin,xmax,ymax"`。这些是 EMF 设备坐标，不能默认等于 AD 坐标。工具报告受支持的文字记录数量、重叠字框、越界，以及被导线、引脚、器件轮廓或圆形穿过的文字（`text_line_conflicts`）；线条按 EMF 映射模式换算，并用记录自带范围核对换算是否可靠。圆弧记录、器件遮挡、参数真实性和视觉重心不在检查范围内。`native_ad.py export` 自动附带同一审查的摘要。

实际审图至少覆盖：

1. 全图的阅读顺序、密度、留白与图签边界。
2. 每个功能区的元件、位号、参数和短线。
3. 芯片长引脚名、引脚号与网络名之间的间隔，晶振、复位和电源等局部。
4. 重复通道的对应关系及隔离回流。
5. PDF/图片与原生工程是否同一版本，实际打印尺寸是否可读。

问题未解决就继续修订，不能把“渲染过几次”代替质量判断。需要真实软件截图时保留真实窗口与原图，不能给导出图套假软件界面。

## 打包

先明确清单。常见原理图交付为 PrjPcb、SchDoc、必要库、完整 PNG/矢量图或单页 PDF、简明复核说明；是否包含报告、PCB 和仿真遵从用户要求。

建立干净暂存目录，不删除原始资料。ZIP 检查 CRC、重复路径、危险路径和预期扩展名；解压到新目录，逐文件比对 SHA-256，再从解压目录复开关键工程。原生打开后复查文件哈希，区分软件生成缓存与交付源文件的改变。

最终说明列出实际验证版本、错误和警告、未完成范围。没有授权不要清理历史交付和可复用缓存。
